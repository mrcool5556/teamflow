Bring the UIX "make it yours" model into Teamflow

George's idea (IDEAS.md, "Customisation idea: design your own look from the UIX library"): use the UIX design library's aspects so people can design their own Teamflow look, with "simple but advanced" editing. This page maps UIX onto what Teamflow already has, then mocks the simple panel, a Design page (desktop and phone), four mixes on a sample board, and the heads-up line. Nothing in the app has changed. The light/dark toggle above only switches this page's chrome; the mixes keep their own colours.

  • Port, don't load: copy the aspect rules into Teamflow's CSS (a new styles/aspects.css) written against Teamflow's own classes and tokens. Loading bundle.css/bundle.js at runtime would bring .uix-* classes Teamflow doesn't use, React components it doesn't need, a Google Fonts @import on every page, and a second token system.
  • Nearest box wins: UIX writes rules like [data-surface="glass"] .uix-card. With a page set to glass and a drawer set to flat, both selectors match and the later rule wins, not the nearer box. In Teamflow each aspect value should set CSS variables on the box that carries the attribute ([data-surface="glass"] { --surface-bg: …; --surface-shadow: …; }) and components read the variables, so inheritance makes the nearest box win.
  • Fonts: all are free to ship. Encode Sans Semi Condensed, Manrope, IBM Plex Mono, Caveat, Pixelify Sans, VT323, Orbitron, Bricolage Grotesque and JetBrains Mono are SIL OFL 1.1; Special Elite is Apache 2.0; Atkinson Hyperlegible has its own free licence (and an OFL "Next" version). The UIX fonts/ folder has the five Machined woff2 files (~81 KB together) but no licence files, so Teamflow should add OFL.txt next to them. Self-host every set in apps/web/public/fonts (no Google request from a self-hosted app); @font-face only downloads a file when that font set is in use, so unused sets cost nothing. Rough size: 15–40 KB per weight, under 400 KB for everything.

Heads-up rules (warn, never block)

  • From the UIX mixer: glass without a see-through theme; paper surface or cut-paper buttons on a dark theme; neon buttons on a light theme; notebook fields without the Paper font; retro box switch without 90s bevel buttons.
  • Teamflow's own: a custom accent that reads under 3:1 on the theme's background (buttons) or 4.5:1 (text on accent); lipped buttons on a light theme; Pixel font with a dense board (cards get taller); Base UI style "Glass" or "Neon" fighting a different surface choice.

6

Per-box overrides

  • How: the same attributes on a part instead of <html>: .drawer[data-surface="paper"], .topbar[data-buttons="flat"]. With aspects written as variables (section 1), the nearest box wins and everything else is inherited.
  • Where it makes sense in Teamflow: three parts only: Topbar, Cards and Drawers and dialogs, each with Surface and Buttons (for example a paper drawer over a machined board, or flat buttons only in the topbar).
  • Worth it? Later. It doubles the Design page (every aspect × 4 targets), most mixes look best with one surface, and the variable-based CSS from step 1 is what makes it possible anyway. Recommend: build the variable approach now, ship whole-app aspects first, add a "Parts" tab with the three targets as a follow-up if George wants it.

7

Risks

  • Contrast: UIX themes pass 4.5:1 for their own token pairs (checked by tools/contrast.py), but Teamflow uses tokens UIX doesn't have (--cell, semantic row/column tints, priority colours, the due chip's amber). Each new theme needs Teamflow's own pairs checked; plan a small contrast test over all 11 themes. Machined Light's gold is 3.9:1 on its page colour.
  • Fonts: Pixel and Neon (Orbitron) change line heights and widths; card titles wrap more and headers can clip. Needs a visual pass at 1440/1024/375 per font set. Self-hosting means adding ~10 woff2 files (OFL/Apache, licences must ship alongside).
  • Performance: Glass (backdrop-filter) on every card in a board of 200+ cards is expensive; apply glass to rows, drawers and dialogs, and give cards a cheaper translucent fill. The paper fibre is one SVG data URL (cached), fine. Soft-inset is pure box-shadow, fine.
  • How much CSS changes: the 8 UI styles live in 119 data-chrome-style selectors across 10 files, and 31 hard-coded font families. Plan: keep UI style as the base (no rewrite), tokenise fonts, add one new styles/aspects.css (~400–600 lines) whose aspects override the base only when set. New profile fields need a schema default (Auto) so old profiles look identical.
  • Scope creep: 11 colour themes × 6 fonts × 5 corners × 7 surfaces × 8 buttons × 4 fields × 3 switches is ~220,000 mixes. Warnings and presets keep it usable; tests should cover each value once, not combinations.

Admin page and Spaces

George's idea (docs/IDEAS.md, "Admin page and Spaces with storage limits"): a server admin page that creates spaces. Admin spaces get the upload allowance the admin sets; free spaces anyone can create, make issues freely, but have a 1 GB upload cap so the server does not bloat. The same page shows server, Discord bot, update, backup and disk status. Nothing is built yet. Frames are drawn with the app's own tokens at real pixel sizes, scaled down. Numbers in the frames are examples, except the disk figures, which were read from production on 2026-11-04.

1 · The model in plain words

A space is a team with a type and an upload allowance

Every team becomes a space. Nothing about boards, roles or invites changes. Each space has a type (Admin or Free) and an upload cap (a number of bytes, or no limit). Only uploads are capped: issues, comments, rows and links never are.

Same thing as a team, or a layer above?

A layer above teams would mean a second membership model, second invites and a migration of every route.

Same thing. Add teams.space_type and teams.storage_cap_bytes. The UI says "space" on the admin page; team Settings keeps saying "team".

The two kinds

Admin space: made by an instance admin on the admin page, with an owner and an allowance the admin types (or no limit). Free space: made by anyone with New team, and each new user's General; gets the default cap.

Default free cap 1 GB, editable on the admin page. Each user may own at most 3 free spaces (General included), also editable, or the cap is easy to dodge.

What counts against the cap

Bytes this space keeps on disk.

Count each stored file once (however many issues link it), files in the Files trash until purged, files on issues in the issue trash, and uploads in progress at their full size. Do not count the database, backups or exports: those are server-level and shown under Disk.

Near and at the limit

Users should never lose an upload halfway.

At 80% the Files drawer meter turns amber and upload zones say how much is left. At 100%, or when a file would not fit, the upload is refused before any bytes are sent, with a message that says what to do. Issues, comments, moves and linking existing files keep working.

Can an admin change type or cap?

Yes, any time, from Space detail.

Lowering the cap below current use deletes nothing; it only blocks new uploads until the space is under. Free → Admin stops it counting toward the owner's 3 free spaces. Changes are written to the activity log.

Existing teams

Production has the Axiom board and personal General teams.

Schema version 4 makes every existing team an Admin space with no limit, so nothing breaks. George can then set caps by hand. Only teams created after the upgrade can be Free.

Server safety floor (extra)

Caps alone do not stop admin spaces with no limit from filling the disk.

Refuse every upload when the disk would drop under 2 GB free (TEAMFLOW_MIN_FREE_DISK), with its own message. The Overview shows the sum of all caps against free disk.

Where the page lives

The Updates and bot panels now sit in team Settings although they are server-wide.

New route /admin, opened from the avatar menu as "Server admin", visible to instance admins only. Settings → Updates becomes a link to it; old API routes keep working.

2 · Admin page · Overview

Server, bot, updates, backups and disk on one page

  • Five status tiles, each with a coloured dot and one or two actions. Details open the existing panels.
  • Server tile does service and port detection: the port the server listens on, whether PUBLIC_URL answers /health, and the systemd or NSSM service state.
  • Disk tile splits uploads, database, backups and the rest (the build measures the backup folder too), and compares allocated caps with free space.
  • "Common fixes" lists how-tos matched to what the checks found (for example, bot stopped → Start bot, sudo not set up → the command to run).

4 · Create space dialog

Name, key, type, allowance, owner

  • Type is two cards. Admin space: the allowance field is enabled, with presets and a "No limit" tick. Free space: the allowance is fixed to the default (1 GB) and the field explains it.
  • Owner defaults to you; pick any user. The owner gets the Owner role, same as New team today.
  • The shared Dialog primitive; on phones it is a full-screen sheet.

7 · At the limit

Uploads stop, with a clear reason; everything else keeps working

  • The web checks the space's remaining bytes before it starts, so a 300 MB file is refused at once, not after 290 MB of chunks.
  • The server checks too (every upload path), answering 413 with code space_storage_full and { usedBytes, capBytes, fileBytes }. MCP, CLI and the Discord bot pass that message on.
  • The upload zone is disabled with the reason. Creating issues, comments, moving and linking existing files are untouched.
  • The server floor uses its own message: "The server is almost out of disk. Uploads are paused for everyone; a server admin has been told."
